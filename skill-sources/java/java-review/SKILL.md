# Java 代码审查

## 执行流程

1. 开始审查前，完整读取下列规则和规范：
   - [代码审查规则](references/代码审查规则.md)
   - [命名](references/编码风格规范-命名.md)
   - [注释](references/编码风格规范-注释.md)
   - [注解](references/编码风格规范-注解.md)
   - [方法结构](references/编码风格规范-方法结构.md)
   - [换行](references/编码风格规范-换行.md)
2. 按代码审查规则确定本次变更范围，只审查本次变更新增或修改的代码。优先使用 code-review-graph 检索代码实体、调用链和影响范围，再读取必要的差异及源文件。
3. 对所有 Java 项目执行通用编码风格、正确性、异常处理、性能、可维护性和安全性检查。
4. 对架构相关规则先验证适用性：只有目标项目确实采用多租户、Dubbo、FastJSON、`BeanCopyUtil`、`Response.success`、组件仓库或对应包结构时，才应用相应规则；不得因项目不存在相关架构而报告问题。
5. 对每项发现给出可定位证据、触发条件、实际影响和具体修复方向；不要把没有行为影响的个人偏好报告为缺陷。
6. 没有发现问题时，明确说明审查范围、已执行的验证和剩余风险。
7. 只读审查不修改代码；只有用户明确要求修复时，才使用 `$java-coding` 实施修改。
8. 未经用户明确要求，不创建 Git 提交。

## 边界

- 审查范围覆盖所有项目的 Java 源码、Java 测试和相关 MyBatis XML。
- 项目或框架专属规则必须有仓库事实作为适用证据。
- 以代码审查规则规定的分类、严重级别和报告格式输出。
