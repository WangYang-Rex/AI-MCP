## 一、OpenClaw 整体架构

OpenClaw 是一个**个人 AI Agent 运行时平台**，核心是一个常驻的 **Gateway 守护进程**。

```
┌─────────────────────────────────────────────────────┐
│                    Gateway (守护进程)                  │
│  ┌───────────┐  ┌──────────┐  ┌──────────────────┐  │
│  │ Agent 运行时│  │ 消息路由  │  │  工具/插件系统    │  │
│  │ (Agent Loop)│  │ (Channels)│  │  (Tools/Skills) │  │
│  └───────────┘  └──────────┘  └──────────────────┘  │
│  ┌───────────┐  ┌──────────┐  ┌──────────────────┐  │
│  │ Session 管理│  │ Cron 调度 │  │  Memory 系统     │  │
│  └───────────┘  └──────────┘  └──────────────────┘  │
└─────────────────────────────────────────────────────┘
         ↕ WebSocket
┌────────────────────────────────────────────────────┐
│  客户端层：WebChat / CLI / macOS App / 钉钉 / 飞书   │
│  Nodes：macOS / iOS / Android 设备                   │
└────────────────────────────────────────────────────┘
```

### 核心组件

| 组件 | 职责 |
|------|------|
| **Gateway** | 常驻守护进程，WebSocket 服务，所有通信的中枢 |
| **Agent Runtime** | 内置 Agent 循环：Prompt 组装 → LLM 调用 → 工具执行 → 结果回传 |
| **Channels** | 消息面：WhatsApp/Telegram/Slack/Discord/Signal/钉钉/飞书/WebChat 等 |
| **Sessions** | 会话管理，JSONL 持久化，支持多会话/子 Agent |
| **Tools** | 内置工具（exec/read/write/browser 等）+ 插件工具 |
| **Skills** | 可复用的指令集，按场景加载（如 PRD 模板、Obsidian 操作等） |
| **Cron** | 定时任务调度（提醒、定期巡检、Dreaming 等） |
| **Memory** | 记忆系统，跨会话持久化 |

### 多 Agent 能力

OpenClaw 支持配置多个 Agent（如我"小策"是产品助手，另有"小工"做工程等），每个 Agent 有独立的：
- **Workspace**（工作目录 + 引导文件）
- **Session 存储**
- **Memory 索引**
- **Skills 配置**

## 二、记忆系统架构

OpenClaw 的记忆系统**完全基于纯 Markdown 文件**，没有隐藏状态。模型只记得磁盘上写了什么。

### 记忆分层

```
┌─────────────────────────────────────────┐
│          MEMORY.md（长期记忆）            │ ← 每次会话开始自动注入
│  精华、偏好、决策、持久事实               │
├─────────────────────────────────────────┤
│     memory/YYYY-MM-DD.md（日记忆）       │ ← 今天+昨天自动注入
│  当日会话流水、决策记录、原始上下文        │
├─────────────────────────────────────────┤
│          DREAMS.md（梦境日记）            │ ← 可选，Dreaming 产出
│  巩固摘要、主题反思、晋升记录             │
├─────────────────────────────────────────┤
│      knowledge/（Obsidian 知识库）       │ ← 按需检索
│  专题笔记、产品文档、归档资料             │
├─────────────────────────────────────────┤
│        Wiki Vault（编译知识库）           │ ← 可选，memory-wiki 插件
│  结构化声明、来源溯源、矛盾检测           │
└─────────────────────────────────────────┘
```

### 各层详解

#### 1. MEMORY.md — 长期记忆（精华层）

- **定位**：紧凑、精选的持久知识
- **内容**：用户偏好、产品决策、行为准则、重要事件
- **注入时机**：每次会话第一轮自动注入到 System Prompt
- **维护方式**：
  - 手动编辑（主人或我直接改）
  - **Dreaming 自动晋升**（Deep 阶段从日记忆中提炼）
- **大小限制**：超过 bootstrap 预算会被截断，需要将细节下沉到 `memory/*.md`

我的 MEMORY.md 里目前包含：
- 产品概况（CRM、财务报销）
- 重要决策记录（PRD 模板规范、群聊知识库规则、方案输出规则等）
- 知识库路径索引
- 经验教训（Lessons Learned）
- 从日记忆中自动晋升的条目

#### 2. memory/YYYY-MM-DD.md — 日记忆（工作层）

- **定位**：每日详细记录
- **内容**：会话摘要、需求分析过程、决策上下文、临时状态
- **注入时机**：今天 + 昨天的文件自动注入
- **检索**：全部文件被索引，可通过 `memory_search` 语义搜索
- **示例**：`memory/2026-05-01.md` 记录了出纳支付需求分析的全过程

#### 3. DREAMS.md — 梦境日记（巩固层）

- **定位**：Dreaming 系统的人类可读输出
- **内容**：Light/REM/Deep 三阶段的巩固摘要
- **作用**：主人可以审阅哪些短期记忆被晋升、哪些被丢弃

#### 4. knowledge/ — Obsidian 知识库（共享层）

- **定位**：与 Obsidian 共享的结构化知识
- **路径**：软链接 → `/Users/wangyang/Documents/Obsidian/openclaw/knowledge`
- **内容**：产品文档、OpenAPI 文档、专题笔记
- **检索**：通过 `obsidian-cli` 或 `memory_search`（配置 `extraPaths`）

#### 5. Wiki Vault — 编译知识库（结构化层）

- **定位**：可选的 memory-wiki 插件，将记忆编译为带来源追溯的 Wiki
- **能力**：结构化声明（Claims）、证据链、矛盾检测、新鲜度追踪
- **工具**：`wiki_search` / `wiki_get` / `wiki_apply` / `wiki_lint`

### 记忆检索机制

```
用户提问
   ↓
memory_search（语义搜索）
   ↓
┌──────────────┐    ┌──────────────┐
│  Vector 搜索  │    │  BM25 关键词  │
│ (语义相似度)  │    │  (精确匹配)   │
└──────┬───────┘    └──────┬───────┘
       └──────┬────────────┘
              ↓
        加权融合排序
              ↓
        memory_get（精确读取）
              ↓
           回答用户
```

**搜索引擎**：SQLite + FTS5（BM25） + 向量嵌入（OpenAI/Gemini/本地 GGUF 等）

**混合检索**：
- **Vector Search**：语义相似（"支付完成"能匹配"出纳付款后"）
- **BM25 Keyword**：精确匹配（错误码、配置键名、人名）
- **Temporal Decay**：旧笔记权重衰减（30 天半衰期）
- **MMR 去重**：避免返回 5 条说的是同一件事

### Dreaming — 自动记忆巩固

这是我比较喜欢的机制，相当于"睡觉时整理记忆"。

```
┌─────────┐    ┌─────────┐    ┌─────────┐
│  Light   │ →  │   REM   │ →  │  Deep   │
│ 分拣暂存 │    │ 主题反思 │    │ 评分晋升 │
│ (不写入) │    │ (不写入) │    │(写MEMORY)│
└─────────┘    └─────────┘    └─────────┘
```

| 阶段 | 做什么 | 写入 MEMORY.md？ |
|------|--------|:---:|
| **Light** | 去重、暂存短期信号、记录强化信号 | ❌ |
| **REM** | 主题归纳、反思摘要 | ❌ |
| **Deep** | 加权评分 → 过阈值门控 → 晋升到 MEMORY.md | ✅ |

**Deep 阶段评分信号**：

| 信号 | 权重 | 说明 |
|------|:---:|------|
| 相关性 | 0.30 | 检索质量 |
| 频率 | 0.24 | 被召回的次数 |
| 查询多样性 | 0.15 | 不同查询/天数 |
| 新鲜度 | 0.15 | 时间衰减 |
| 跨日巩固 | 0.10 | 多天反复出现 |
| 概念丰富度 | 0.06 | 概念标签密度 |

晋升必须同时通过 `minScore`、`minRecallCount`、`minUniqueQueries` 三道门槛。

---

### 会话压缩前的自动记忆刷写

当会话上下文快满时，OpenClaw 会触发 **Compaction**（压缩）。在压缩前，系统会跑一轮静默 turn，提醒 Agent 把重要上下文存到记忆文件，防止压缩丢失关键信息。

```
会话进行中 → 上下文接近上限 → 触发 Memory Flush → Agent 写入记忆 → 然后 Compaction
```

## 三、我的记忆实践

作为"小策"，我的记忆流是这样的：

```
每次会话开始：
  1. 读 AGENTS.md（工作规范）
  2. 读 SOUL.md（角色定义）
  3. 读 memory/knowledge.md（知识库使用规范）
  4. 读 memory/YYYY-MM-DD.md（今天+昨天）
  5. 读 MEMORY.md（长期记忆）

会话中：
  - 重要决策/需求变更 → 即时写入 memory/YYYY-MM-DD.md
  - 产品功能更新 → 更新 products/ 目录

会话结束/定期：
  - Dreaming 系统自动巩固日记忆 → 精华晋升到 MEMORY.md
  - 我也可以手动整理 MEMORY.md
```

**实际例子**：你在我的 MEMORY.md 里能看到 `Promoted From Short-Term Memory` 区块，那些就是 Dreaming 系统自动从日记忆中提炼出来的条目，每条都带有来源引用（`source=memory/2026-05-01.md:18-18`）和置信度分数。

## 总结

| 特性 | 实现方式 |
|------|----------|
| **无隐藏状态** | 一切记忆 = Markdown 文件 |
| **分层存储** | 精华(MEMORY.md) → 日记忆(YYYY-MM-DD.md) → 知识库(knowledge/) |
| **语义检索** | Vector + BM25 混合搜索 |
| **自动巩固** | Dreaming（Light → REM → Deep） |
| **防丢失** | Compaction 前自动 Memory Flush |
| **可审阅** | DREAMS.md + 来源引用 + 置信度分数 |
| **可扩展** | Wiki Vault / Obsidian / 多 Embedding Provider |

整套系统的设计哲学是：**文件比记忆可靠，显式比隐式可靠**。所有记忆都是你能看到、编辑、版本控制的 Markdown 文件，没有黑盒。
